# 对话中的账号连接

核验日期：2026-11-08。用户只点击官方授权链接；智能体在后台启动、查询和取消登录。没有浏览器控制或终端界面依赖，不要求用户执行命令或把授权码发进聊天。

## 选择认证路径

1. 后台检查依赖，运行一次 `auth/check.sh` 验证已有认证。`doctor.sh` 默认不检查认证，不能把其 `ready` 当作已登录。
2. 已有有效 profile 或环境凭证：直接复用，不强制网页登录。
3. 本地宿主，用户浏览器与后台同机：创建链接授权会话。智能体知道执行环境时直接选择，不让用户判断 socket、localhost 等技术细节。
4. 远程容器、服务器或不可达的回调环境：使用宿主已连接的腾讯云账号。没有连接能力时返回明确限制并保留需求，不能把远端 localhost 链接当作用户可用的授权入口。

依赖缺失或版本不兼容由智能体在后台按宿主能力处理；安装方式参见[官方安装指南](https://cloud.tencent.com/document/product/440/34011)。不能安装时说明具体缺失能力，不把命令清单当成用户的购买步骤。

## 后台会话接口

以下命令仅供智能体调用，不要求用户执行。准确选项以脚本 `--help` 为准。

```bash
bash scripts/auth/login.sh --start --profile work --execution-context local --timeout 300
bash scripts/auth/login.sh --status <session_id>
bash scripts/auth/login.sh --cancel <session_id>
```

启动返回 JSON，其中 `auth_url` 是本次原生 tccli 生成的腾讯云链接，`session_id` 用于后台查询，`expires_at` 表示有效期。`--execution-context` 默认 `unknown`；仅明确同机时选 `local`，远程选 `remote`，后两种未知/远程情况返回 `needs_host_auth` 而不启动回调。保存同一会话；等待中的重复启动应复用已有会话，不不断打开新链接。后台进程必须在等待用户期间存活；宿主会在工具调用结束后回收进程时，不能声称此流程可用。

| 状态 | 对话里的下一步 |
|---|---|
| `starting` | 后台准备授权入口，暂不发送空链接 |
| `awaiting_authorization` | 发送官方链接，等待用户授权；不要求回传验证码 |
| `verifying` | 告知已收到授权、正在验证账号连接，不启动第二次登录 |
| `stopping` | 后台正在结束旧会话，等结束后再创建新链接，不重复要求用户授权 |
| `ready` | 登录和只读验证成功，继续原购买需求 |
| `failed` | 用可理解语言说明具体阶段失败；区分授权失败与 API 权限不足 |
| `expired` / `cancelled` | 旧链接不再使用，需要继续时创建一个新会话 |
| `needs_host_auth` | 当前宿主缺少可达回调/账号连接能力，不能靠对话中的验证码补救 |

不要将“用户说已授权”“网页登录页已跳转”或“本地存在凭证文件”当作验证成功。`DescribeRegions` 成功也不意味着所有 CVM、VPC、TAT 操作都有 CAM 权限。

`AUTH_CHECK_FAILED` 表示网页登录后的只读验证失败，不等于凭证失效。先用同一认证来源在后台复查连接与权限；复查成功直接接续原需求，不让用户再点授权链接。网络/DNS 故障与 CAM 权限不足分别处理，只有明确的认证失效才进入重新授权路径。

## 用户可见的三段交互

开始：

> 我会按“国内访问的个人博客、每月约 100 元”继续准备方案。请点击本次提供的“连接腾讯云账号”链接，在腾讯云页面选择账号并授权。完成后回到这里即可；不用执行命令或复制验证码。本次只准备方案，尚未购买。

链接必须是真实返回值，不能使用占位链接或上次会话的地址。tccli 原生页面可能申请账号全读写权限，应按页面事实说明，不把本轮只做询价说成平台只授予查询权限。

收到回调并验证后：

> 账号已连接。我继续查博客所需的服务器和联网费用，稍后给你一份可以直接确认的方案。

过期或失败：

> 这次授权没有完成，旧链接已失效。你的博客需求和预算已经保留，我会提供新的授权链接继续。

只有确认过期才说过期；已有 API 认证有效但某操作权限不足时，说明缺少该操作权限，不要求重复登录。

## 实现与环境边界

原生 tccli 的网页登录会生成官方 URL、接收本机回调、交换并保存凭证。封装仅适配链接输出、回调监听与会话生命周期，不修改已安装 tccli 文件，不自行实现 OAuth 换证，不把凭证写进会话状态或聊天。

本次实测中，原生固定起始端口 9000 的通配地址监听与 macOS 上已有的 loopback 服务共存，导致网页登录后连接重置而 CLI 一直等待。链接授权采用独立的严格 loopback 监听，避开这一冲突；不会停止用户原有服务。

当前原生手动模式 `tccli auth login --browser no` 会要求在原终端粘贴一段含授权信息的编码内容，**它不是适合发送到聊天的普通验证码**，也不属于本 Skill 的用户流程。不要退回这种方式，不从浏览器页面、历史记录、剪贴板或 URL 抽取令牌来补救登录。

本机回调不等于远程授权中继。若宿主未来接入可信授权连接器，应由连接器负责认证、隔离和凭证保管；不能临时暴露回调公网端口或借用未经确认的第三方服务。[官方网页登录流程](https://cloud.tencent.com/document/product/440/111345)

## 多账号与已有环境凭证

后台 profile 优先级：显式 `--profile` → `TENCENT_CVM_PROFILE` → `TCCLI_PROFILE` → `default`。profile 是本地配置名，面向用户说“腾讯云账号”，不让用户选择或记忆 profile。

原生 tccli 显式 `--profile` 会禁用环境密钥读取。未选择 profile 且有完整环境凭证时，保留环境认证；网页授权后固定已选 profile。直接 tccli 不识别本 Skill 的 `TENCENT_CVM_PROFILE`。[官方配置文档](https://cloud.tencent.com/document/product/440/34012)

购买计划校验 profile 与认证来源，尚未绑定云账号 UIN。确认方案时展示已核实的账号标识；同名 profile 换号后重新准备方案，不能沿用旧账号批准内容。不要读取 `~/.tccli/*.credential` 或执行会回显密钥的配置列表来识别账号。

企业 SSO 是另一条组织认证路径，依赖组织门户；优先复用宿主已有的 SSO 登录态。没有连接能力时说明限制，不擅自改用另一种认证覆盖它。[官方 SSO 文档](https://cloud.tencent.com/document/product/440/132374)

仅在用户要求退出时清理对应登录态。取消等待中的授权会话不代表撤销账号授权，也不会删除已有凭证。
